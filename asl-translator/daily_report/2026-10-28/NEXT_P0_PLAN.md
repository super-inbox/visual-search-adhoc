## 决策与已有证据

Production Gemini 与 Uni-Sign 已经做过更大规模评测。下一轮应复用已有基线，验证新方法相对基线的增量，不重复安排原有模型的大规模比较。执行时先登记对应 benchmark、样本 ID、输入窗口、模型/代码版本及预测文件；本文不把下述 45 例诊断结果当成大规模评测结果。

参考：[10 月 27 日工作报告](../2026-10-27/ASL_WORK_REPORT.md)、[10 月 28 日进展评审](PROGRESS_REVIEW.md)。

当前 45 例开发诊断证据：

- 全局 token trigram 防重复使循环 9→0，chrF 23.76→25.49，但改变了 15 条原本没有循环的输出，包括合法重复；尚不能作为默认解码策略。
- 采样改进在不同输入域上的收益不一致；当前候选池重排收益很小。暂停继续搜索这两类参数。
- OpenFS 和检测器已能产生输出，但尚无可靠标签证明自动拼写提取有效。OpenFS 使用手部关键点，不能将它的运行结果称为已验证的手部 RGB Fusion。
- 没有新的、已经确认可上线的 Fusion 收益。专家招募继续进行，但下面的实验准备与模型对照可以并行。

## P0-1：手部 RGB / fingerspelling 局部增强

目标：验证增加手部视觉信息能否修复 Uni-Sign 的具体内容错误，再决定是否投入融合训练。先做局部增强，不让大模型自由改写整句。

### 实验顺序

| 阶段 | 控制条件与操作 | 要回答的问题 |
|---|---|---|
| A：已知区间识别 | 用独立人工确认的拼写区间，提供连续、清晰的手部 RGB；对照现有关键点识别器 | 定位已正确时，字母能否读对？RGB 是否带来额外信息？ |
| B：自动定位＋识别 | 固定 A 阶段识别器，改用自动检测区间 | 自动定位损失了多少准确率？瓶颈在区间还是识别？ |
| C：有限融合 | 将有证据的拼写候选用于 Uni-Sign 中对应的人名/专有名词；无法可靠对应则保留原输出 | 局部识别正确能否改善整句，是否误伤原本正确内容？ |

A 阶段是人工区间下的诊断实验，必须单独报告，不能包装成自动端到端成绩。标注和识别过程中不向模型提供英文 reference、目标名字、音轨或答案字幕。

### 数据与输出要求

- 包含已确认的拼写正例、普通手语等易误报负例，以及原本 Uni-Sign 正确的对照例；不要只筛选看起来成功的名字。
- 保存源视频 ID/hash、区间起止时间、crop 坐标、帧时间戳、检测分数、原始字母串、候选及弃权原因。
- 区分源视频时间、clip 相对时间和帧索引。只有窗口级时间时，逐字母时间戳必须留空，不能伪造对齐。
- 检测报告定位重叠/召回与负例误报；识别报告 CER 和完整词准确率；融合报告正确修复、错误替换及整句内容损伤。
- 不使用未经校准的模型自报 confidence 作为自动替换依据。

决策门槛：若已知区间下仍无法可靠读出字母，先改识别器，暂缓扩大自动检测和 Fusion；若 A 有效而 B 明显退化，优先修定位。只有 C 显示实际内容改善，才进入更大范围端到端验证。具体接受阈值在查看确认集结果前登记。

交付：区间/标签清单、关键点与 RGB 配对结果、A/B/C 分阶段指标、误报与误伤案例，以及继续/停止结论。

## P0-2：OpenAI 离线对照，与 P0-1 并行

目标：分别回答能否替代 production Gemini，以及是否能补充 Uni-Sign 的特定弱项。不预设通用模型优于专用模型。

OpenAI 官方文档支持单次请求输入多张图片，可按时间顺序提供帧及时间戳；这不构成 ASL 识别能力的证明。输入方式参考：[Images and vision](https://developers.openai.com/api/docs/guides/images-vision)。执行时选定可用的视觉模型，固定可用的模型快照或记录精确模型标识与调用日期。

### 第一轮：只换模型

- 从已有大规模 benchmark 取预先固定的代表性试跑子集，不以这 45 条反复研究的案例作为唯一依据。
- 复用 production Gemini 的视频窗口、抽帧序列、分辨率、任务要求和输出字段；API 适配差异单独记录。
- 复用对应 Gemini 与 Uni-Sign 预测作为基线；输入或配置不匹配的记录不能强行做配对比较。
- 不给 reference、已有翻译、音轨或答案字幕；保留原始响应、解析失败和空输出，不能从分母中剔除失败。
- 统计整体质量、遗漏、关键内容错误、成本、延迟和失败率。试跑用于筛选，冻结方案后再在确认集作结论。

### 第二轮：输入增强与互补性

只有第一轮或明确错误类别显示潜力，再尝试连续短窗口、手部高清 crop；结果标为“模型＋输入方案”的收益，不能归因于单纯换模型。

按相同病例统计四格：两者都对、仅 Uni-Sign 对、仅 OpenAI 对、两者都错。正确与否需可靠标签/盲评，不能用输出不一致代替。重点看 Uni-Sign 错误中 OpenAI 能修复的比例，以及反向误伤。如果互补成立，再研究无需 reference 的选择或局部融合规则；oracle 选择只作为潜在收益上界。

交付：基线来源清单、可复现运行配置、逐例预测与指标、互补性表、成本/延迟统计，以及“替代候选 / 局部 specialist 候选 / 暂停”的结论。暂不更换 production 模型。

## P0-3：条件触发的防重复，小规模验证

目标：减少全局 no-repeat 规则对合法语言重复的损伤。

- 对输出检测异常词/短语循环，仅对命中病例重新生成；未命中病例保持原输出。
- 增加正常重复表达的负例，检查检测器误报。不能把第二次出现 `I'm` 等合法表达直接视为循环。
- 需要生成新的候选并验证内容；当前候选池重排已基本无收益，不再重复同一实验。
- 分开报告循环减少、正确内容恢复、内容丢失、触发率及新增成本。简单删除重复只算格式修复，不能宣称翻译准确率提升。

交付：触发规则、逐例原始/修复输出、未触发输出一致性检查、正常重复负例结果及继续/停止结论。

## 何时扩大评测

| 方向 | 下一步规模决策 |
|---|---|
| OpenAI 新模型 | 代表性子集试跑后，有可重复正向信号则跑既有完整 benchmark |
| 拼写 specialist / 局部 Fusion | 先验证已知区间识别，再自动定位，再扩大端到端验证 |
| 条件触发防重复 | 先证实内容修复与误伤可接受，再扩大 |
| 当前采样参数 / 当前候选重排 | 暂缓；当前证据不足以支持扩大投入 |
| 原有 Gemini / Uni-Sign 基线 | 复用；仅对输入、模型或代码版本变化导致不可比的部分补跑 |

大规模评测优先服务于会改变部署或研发决策的新方案。不要因诊断集平均分略涨，就将所有方案直接扩跑。

### 确认收益的规则

1. 45 条诊断病例继续作为开发集。冻结配置与接受阈值后，在未参与调参的数据上确认；若原有 benchmark 也反复用于选方案，另留独立确认集。
2. 同一视频配对比较，按源视频/signer 分组估计置信区间，避免把同一来源的相邻片段当作独立样本。样本规模依据预期效应、方差和标注预算制定，不预设一个数字就足以证明收益。
3. 同时报整体翻译指标、关键内容正确率、原本正确病例的退化率，以及成本、延迟、失败率；分层看拼写、长句、循环等类别，保留总体分布视角。
4. 专家优先评审新旧分歧与疑似修复例，并混入随机对照；若富集抽样，分层结果与总体估计分开报告。不得仅展示成功案例。
5. 复用基线前检查样本、窗口、输入 hash 和配置。新版生产接口的格式修复（如 R03 部分 batch 解析失败）单独记录版本，不把工程修复与模型能力混在一起。
