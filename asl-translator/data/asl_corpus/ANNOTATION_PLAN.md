# Manual Annotation Plan

Companion to `corpus_inventory.csv` (full 13-video inventory) and
`annotation_queue.csv` (the selected batch below). No transcript content is
generated by this plan — it only decides *which* videos to annotate and
*why*; the English gloss itself must come from a human watching the video in
`asl-translator/asl-ground-truth-annotator/`.

## What to do manually, step by step

For each video in the batch, in priority order:

1. **Launch the tool** (from the repo root):
   ```
   python3 -m http.server 8934 --bind 127.0.0.1 -d asl-translator/asl-ground-truth-annotator
   ```
   Open `http://127.0.0.1:8934/index.html`.

2. **Load the video** via "Load video…", picking the matching `.mp4` from
   `asl-translator/data/asl_corpus/videos/`.

3. For item 3 (`1320_1000022357_137.2s`) only: **Import** the existing
   candidate first — `ground_truth_candidates/1320_1000022357_137.2s.json`
   — via "Import SRT/JSON…". This loads the burned-caption-derived text as
   your starting point. Watch the actual signing (not just the caption
   band) and correct any segment where the caption text doesn't match what
   was actually signed; adjust timing to the real sign boundaries. Also
   note in the exported JSON's `meta` whether this looks like an ASL
   rendition that was then captioned, or an English source that was
   interpreted into ASL — that's the open question blocking this item from
   official metrics.

   For all other items (1, 2, 4, 5, and optionally 6): there is no existing
   file to import — start from scratch with "+ Add segment (at playhead)".

4. **Transcribe/verify**: play through, set in/out points with `S`/`E` (or
   the on-row buttons), type the English caption per segment, repeat to the
   end. Use `Shift+←`/`Shift+→` for fine boundary nudges.

5. **Set provenance before exporting** — this is the step that marks the
   output as human/manual, not a model guess:
   - Set `gt_kind` to `human` on every segment (the importer already does
     this for `.srt` imports, and it's the default for segments you add
     from scratch — verify it wasn't left as `model` if you started from a
     baseline0 JSON by mistake).
   - Check the `verified` checkbox once you've reviewed the full pass
     start to finish.
   - For item 3, additionally record the production-direction finding
     (captioned-ASL vs. interpreted-English) as free text in whatever notes
     field the export's `meta` block allows.

6. **Check the validation summary** is clean (or that any remaining
   warnings — e.g. real overlapping segments in multi-signer content — are
   expected and intentional).

7. **Export both SRT and JSON.**

## After annotating: making these items official

Once a video has a file under `ground_truth/`:

1. Add an entry for it to `evaluation_set.json` (`reference_status:
   "verified_gold"`, `usable_for_official_metrics: true`) so
   `asl-translator/asl-eval/status.py` picks it up.
2. Run `asl-translator/asl-eval/status.py` to confirm it now reports
   `ready_for_official_metrics` wherever a matching prediction already
   exists (items 1, 2, 4, 5 in this batch already have baseline0
   predictions and become scoreable immediately; item 3 and the optional
   item 6 will need a prediction generated first, e.g. via
   `asl-translator/asl-eval/run_current_model.py`).
3. Score with `asl-translator/asl-eval/evaluate.py` as usual.

This plan does not perform any of steps 1–3 above, and does not call any
model or external API — those are separate, later steps once real
human-verified transcripts exist.
