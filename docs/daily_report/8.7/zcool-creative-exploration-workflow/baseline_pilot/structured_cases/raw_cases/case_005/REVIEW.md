# Review — case_005（视觉盛宴：探索LOGO设计之旅，负面样本）

1. **案例是什么类型？** Logo 成品展示（logo_showcase），实为设计师作品集合，非单一项目案例。
2. **属于什么行业？** 不适用——无单一行业/客户。
3. **页面是否说明项目背景？** 否，这是本案例被选为负面样本的核心原因。
4. **页面展示了哪些设计阶段？** 无——只有最终 Logo 成品展示。
5. **哪些阶段有明确文字证据？** 无。
6. **哪些阶段只有视觉证据？** 无法判断（图片不可见），且即使可见，15张图对应的很可能是不同项目的最终成品，不构成单一工作流的视觉证据。
7. **是否展示候选方案？** 否。
8. **是否展示方案选择或修改？** 否。
9. **能否恢复真实步骤顺序？** 不适用——没有可排序的步骤。
10. **哪些内容重复？** 无法判断。
11. **哪些内容只是最终 Mockup？** 全部15张图片语义上都是"最终展示"（`is_final_showcase=true`），无一例外。
12. **哪些内容应该排除？** 泛论性文案（"LOGO很重要"式表述）本身信息密度低，虽未违反清洗规则不需要物理删除，但在 `usage_recommendation` 判断时不计入有效工作流证据。
13. **哪些工作流字段缺失？** 全部 25 个 stage_type（详见 `missing_stages`）——这是本 Pilot 5 个案例中缺失范围最大的一个,预期之内。
14. **案例完整度是多少？** `showcase_only`——精确命中该等级的定义（"只有最终成品/Mockup，没有任何过程证据"）。
15. **是否适合工作流训练？** 否，明确不适合。
16. **是否只适合作为视觉参考？** 理论上如果图片可见、且能确认这15张图属于统一风格/项目，或许可作为"最终效果参考"，但由于是多项目合集且图片不可得，本 Pilot 判定为 `not_recommended`。
17. **需要多少人工复核？** 低——不是因为案例质量好，而是因为**结论本身很清楚（不可用），不需要反复判断**，这与 case_003/case_004"需要大量人工才能判断是否可用"的情况相反，属于清洗规则里"能被自动化快速排除"的正面例子。

## 负面样本的价值

本案例验证了 schema 与清洗规则能够：
- 正确将 `workflow_completeness` 判定为最低等级 `showcase_only`；
- 在没有可提取步骤时，`workflow_extraction.json` 的 `steps` 数组保持为空，而不是编造凑数的步骤；
- `missing_stages` 能完整列出全部 25 个未覆盖阶段，形成清晰的"什么都没有"的记录，而不是留白或跳过。
