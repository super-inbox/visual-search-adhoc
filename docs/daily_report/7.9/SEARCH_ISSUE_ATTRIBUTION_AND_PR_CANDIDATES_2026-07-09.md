# Search Issue Attribution and PR Candidates — 2026-07-09

## Overview

This document synthesizes everything gathered across this project's Curify search-relevance audit into a single root-cause attribution and PR-candidate backlog:

- The 68-query gold-set execution and first-pass metadata-only relevance labeling (`curify_search_auto_collect_with_claude_relevance_2026-07-07.csv`, `CURIFY_SEARCH_RELEVANCE_SUMMARY_2026-07-07.md`).
- The 42-case P0 manual-review prioritization plan (`P0_MANUAL_REVIEW_AND_SCREENSHOT_PLAN_2026-07-09.md`).
- The 12-case representative sample that received full visual review of Curify's own screenshots plus cross-platform competitor screenshots on Bing, Google, Canva, and (manually) Pinterest (`VISUAL_RELEVANCE_AND_COMPETITOR_COMPARISON_2026-07-09.md`, `COMPETITOR_SCREENSHOT_INDEX_2026-07-09.md`, `COMPETITOR_SCREENSHOT_FINAL_CHECK_2026-07-09.md`, and the `competitor_screenshots/` folders themselves).

The goal here is to move from "68 queries failed for various reasons" to "here are the specific engineering fixes worth proposing, ranked by confidence and impact." This is an attribution and planning document, not the final consolidated work report — no production code has been touched, nothing has been staged or committed, and the final report is still pending per prior instructions.

**Evidence tiers used below**, in descending order of confidence:
1. **Visually confirmed** — one of the 12 cases with a directly-inspected Curify screenshot *and* directly-inspected competitor screenshot(s) on at least one platform.
2. **Metadata-confirmed** — one of the 42 P0 (or 26 P1) cases with a Claude-read text-metadata label, screenshot on disk but not yet cross-referenced against a competitor.
3. **Inferred pattern** — a root-cause category assembled by pattern-matching query text/structure across the 68-query set, not yet individually verified.

## Root-Cause Groups

### 1. `zero_result`

- **Affected query count:** 11 of 68 (16.2%)
- **Representative queries:** Amazon EBC enhanced brand content layout; Amazon Vine review request insert card; TikTok GRWM product placement mockup; 亚马逊A+页面模块设计; 社群接龙团购价目表; 私域用户运营SOP流程图; 私域裂变任务宝海报; RTI intervention tracker template; WIDA can-do descriptors chart; first then board autism; sub tub emergency lesson plan folder cover
- **Likely cause:** Two distinct sub-patterns bundled under one tag: (a) acronym/jargon terms (EBC, Vine, GRWM, RTI, WIDA) not recognized as valid search tokens at all, causing the query to return nothing rather than falling back to a broader match; (b) genuine content-library gaps for niche operational/administrative asset types (private-domain-marketing SOP flowcharts, sub-tub folder covers) that plausibly don't exist in Curify's template library yet.
- **More likely:** Mixed — retrieval issue for (a), content supply issue for (b). 7 of 11 are marketing/e-commerce operational assets, which skews this category toward content supply.
- **Evidence from Curify screenshots:** `Amazon EBC enhanced brand content layout` shows a literal "No results for..." page with only generic topic-browse fallback tiles — no attempted query broadening at all, unlike most other FAIL cases which show Curify's broadened-query banner. This absence of even an attempted broadening is itself a signal that the acronym-bearing query short-circuited before reaching the normal fallback path.
- **Evidence from Bing/Google/Canva/Pinterest screenshots:** Visually confirmed for `Amazon EBC enhanced brand content layout` — Bing and Google are both flooded with real "Amazon EBC/A+ Content" design-service listings, and Pinterest has a pin literally titled "EBC / A+ Content." This is the single strongest, most unambiguous retrieval-gap example in the entire sample: the content is abundant everywhere except Curify.
- **Suggested fix direction:** Add acronym/jargon-term recognition (EBC, A+, Vine, GRWM, RTI, WIDA) to the NER/entity layer so these queries at least reach the normal broadened-fallback path instead of returning a hard zero. Separately, treat the private-domain-marketing-ops cluster as a content-library gap (see Section: Content-Library Gaps).

### 2. `low_result`

- **Affected query count:** 3 tagged `low_result` (Amazon brand story module design, 亚马逊评论截图水印素材, IEP accommodations checklist visual); 14 total by the `visible_result_count ≤ 3` metric (includes the 11 zero-result rows)
- **Representative queries:** Amazon brand story module design (2 results); IEP accommodations checklist visual (3 results)
- **Likely cause:** Under-retrieval combined with weak ranking — a small number of loosely-adjacent results are returned instead of either a confident zero or a fuller, better-ranked set.
- **More likely:** Retrieval issue, with a ranking/fallback component — see the `ranking / fallback issue` category below for the specific mechanism.
- **Evidence from Curify screenshots:** `IEP accommodations checklist visual` — only 1 of the CSV's counted 3 results actually rendered a visible thumbnail in the screenshot (a generic "running" warm-up chart), a capture/rendering artifact independent of the relevance problem itself.
- **Evidence from Bing/Google/Canva/Pinterest screenshots:** Visually confirmed for `IEP accommodations checklist visual` — Bing, Google, and Pinterest all show abundant exact "IEP Accommodations Checklist" products; Canva has real IEP-specific content once fully loaded. Three of four competitor platforms strongly outperform Curify's 3-result showing.
- **Suggested fix direction:** Same multi-path retrieval fix as `missing_content_type` below — route by expected content type so a checklist/administrative-document request pulls from a broader candidate pool instead of the same narrow path used for general visual queries.

### 3. `wrong_decomposition`

- **Affected query count:** 29 of 68 (42.6%) — the single most actionable pattern in the dataset
- **Representative queries:** NCT Dream photocard template ("dream" → Dream of the Red Chamber); maker space label set printable ("space" → outer space/astronomy); dreamcore aesthetic moodboard ("moodboard" → generic F&B brand moodboards); genshin impact Furina fanart wallpaper 4k (IP name dropped entirely); 光与夜之恋 卡面设计参考图 (game name dropped, matched on "night" instead)
- **Likely cause:** Curify's query understanding repeatedly locks onto one generic, high-frequency word inside a longer/qualified query and drops the qualifying context (the proper noun, the compound-noun modifier, or the style qualifier).
- **More likely:** Retrieval issue (query-understanding/decomposition layer specifically), not a taxonomy or content gap — in every visually-confirmed case, the correct content demonstrably exists elsewhere.
- **Evidence from Curify screenshots:** Directly visible in every one of the 6 visually-reviewed `wrong_decomposition` cases — e.g., `NCT Dream photocard template`'s screenshot shows Curify's own broadened-query banner explicitly reading "NCT Dream photocard design... K-pop photocard layout" and then still returning Dream-of-the-Red-Chamber scrolls, proving the system identified plausible broadened queries but the retrieval step failed to act on them.
- **Evidence from Bing/Google/Canva/Pinterest screenshots:** Visually confirmed for all 6: Bing/Google/Pinterest return abundant, precisely on-topic results for every one (NCT Dream photocard templates, real Zones-of-Regulation posters, exact Furina 4K fanart, etc.). Canva is more mixed but 2 of 3 apparent Canva "gaps" in this group were later corrected (see `COMPETITOR_SCREENSHOT_FINAL_CHECK_2026-07-09.md`) to show Canva suffering a milder version of the *same* decomposition weakness rather than a hard content gap — direct supporting evidence that this is a retrieval-layer problem class, not unique to Curify's content but showing up wherever decomposition logic is weak.
- **Suggested fix direction:** NER generalization / named-entity protection (primary fix) plus Chinese segmentation improvements for the Chinese-language subset — see PR candidates below.

### 4. `bad_relevance`

- **Affected query count:** 48 of 68 (70.6%) — the broadest tag, co-occurring with nearly every other category
- **Representative queries:** All 12 visually-reviewed cases carry this tag; also 手冲咖啡工作室视觉手册 (ethnic-costume and anime-studio content instead of coffee-studio manuals), 美妆博主个人IP视觉设计 (mythological figures instead of beauty-blogger IP content)
- **Likely cause:** This is the umbrella symptom, not a distinct mechanism — nearly every other category (decomposition, segmentation, NER, alias gaps, content gaps) manifests as "bad_relevance" at the surface level. Used alone (without a more specific co-tag) on only 1 of 48 rows, confirming it is almost always paired with a more specific cause.
- **More likely:** Depends entirely on the co-occurring tag — see the specific category for that determination.
- **Evidence from Curify screenshots:** Visually confirmed across all 12 sampled cases — every one shows a coherent but topically wrong result grid (not corrupted, not blank), consistent with a matching/ranking failure rather than a rendering or infrastructure failure.
- **Evidence from Bing/Google/Canva/Pinterest screenshots:** Visually confirmed across all 12 — Bing, Google, and Pinterest returned on-topic results for essentially all 12, making "the content doesn't exist" an untenable explanation for the majority of this tag's volume.
- **Suggested fix direction:** No standalone fix — resolved by fixing the more specific co-occurring root cause (decomposition, segmentation, NER, alias, or content-library gap) in each case.

### 5. `missing_content_type`

- **Affected query count:** 22 of 68 (32.4%)
- **Representative queries:** maker space label set printable (returned moodboards/photos, no printable-label template type); 低饱和国风茶包装设计 (no packaging-mockup type returned); zones of regulation poster classroom (no poster/framework type); clean girl aesthetic skincare packaging mockup (no packaging-mockup type); 国货美妆联名限定包装 (no packaging type)
- **Likely cause:** A single retrieval path appears to be used regardless of the requested asset *format* — a query asking for a printable label set, a packaging mockup, or a classroom poster instead returns generic photography/moodboard-type results, suggesting the system isn't routing by expected output/content type.
- **More likely:** Retrieval issue (routing/multi-path problem), not a content gap — for at least the 4 visually-reviewed cases in this group (maker_space, low_saturation, zones_of_regulation), competitor platforms demonstrate the correct content-type niche is well-served elsewhere in the exact requested format (printable labels, packaging photography, posters).
- **Evidence from Curify screenshots:** `zones of regulation poster classroom`'s screenshot shows generic K-12 vocabulary flashcards and a library-scene photo — a completely different content *format* than the poster/chart format every competitor returned, even setting aside subject-matter mismatch.
- **Evidence from Bing/Google/Canva/Pinterest screenshots:** Visually confirmed — all four competitor platforms return the poster/chart format specifically for `zones of regulation poster classroom` (the most unanimous case in the whole sample), and Bing/Google/Pinterest return the printable-label format for `maker space label set printable`.
- **Suggested fix direction:** Multi-path retrieval based on subject, style, scene, output format, era, and mood (see PR candidates below) — route queries with an explicit expected-output-type signal (printable, mockup, poster, chart) toward a content-type-aware retrieval path.

### 6. `competitor_gap`

- **Affected query count:** 18 of 68 (26.5%); 17 of the 42 P0 cases carry this tag per the P0 plan (one additional row net after re-tagging)
- **Representative queries:** All 8 `competitor_gap`-tagged cases in the 12-case visual sample: NCT Dream photocard template, Y2K chrome skincare launch poster, K-beauty glass skin brand launch visual, zones of regulation poster classroom, coding unplugged activity cards, genshin impact Furina fanart wallpaper 4k, IEP accommodations checklist visual, 光与夜之恋 卡面设计参考图
- **Likely cause:** This tag specifically means "Claude's first-pass text-metadata read suspected competitors would surface this content." That suspicion has now been visually confirmed for all 8 sampled cases plus 4 more from the wider 12-case sample.
- **More likely:** Retrieval issue, not a content or taxonomy issue — this is now the most strongly evidenced category in the whole audit, because it's the one directly tested against real competitor screenshots rather than inferred.
- **Evidence from Curify screenshots:** Every one of the 12 sampled cases shows Curify visibly failing on-screen (wrong subject, wrong format, or hard zero).
- **Evidence from Bing/Google/Canva/Pinterest screenshots:** This is the category the whole 12-case competitor-screenshot exercise was built to test — see the dedicated "Strongest evidence from competitor screenshots" section below for the full rollup.
- **Suggested fix direction:** Same as `wrong_decomposition`/`missing_content_type` — this tag is a consequence, confirmed by competitor evidence, not a distinct mechanism requiring its own fix.

### 7. Chinese segmentation issue

- **Affected query count:** ~17 Chinese-language queries show plausible segmentation-loss patterns (inferred; not a native CSV tag)
- **Representative queries:** 低饱和国风茶包装设计 (低饱和+国风 qualifier likely dropped, matched generic "food/packaging"); 光与夜之恋 卡面设计参考图 (game-name compound dropped); 私域用户运营SOP流程图 (private-domain-marketing compound noun, zero result); 手冲咖啡工作室视觉手册 (pour-over-coffee-studio compound dropped, matched "ethnic group"/anime-studio); 小红书图文笔记模板 数字标题 (platform-specific compound dropped)
- **Likely cause:** Tokenization of Chinese compound/qualified noun phrases appears to lose the qualifying prefix (低饱和, 国风, 私域, 手冲) and match only a shorter, more generic remaining substring — the same failure shape as `wrong_decomposition` in English, but specific to how Chinese segmentation handles multi-character compound qualifiers without whitespace boundaries to help.
- **More likely:** Retrieval issue (segmentation is a pre-retrieval NLP step), not a taxonomy or content issue.
- **Evidence from Curify screenshots:** Visually confirmed for `低饱和国风茶包装设计` — the screenshot shows Organic Rolled Oats, Double Chocolate Cookies, and Italian Pasta Sauce, i.e., a match on "packaging/food product" broadly, with zero trace of "低饱和" (low-saturation) or "国风" (Chinese-style) as constraints.
- **Evidence from Bing/Google/Canva/Pinterest screenshots:** Visually confirmed — Bing, Google, and Pinterest all return abundant, precisely low-saturation, Chinese-style tea packaging designs for this exact query, proving the qualifiers are meaningful, searchable concepts that Curify's segmentation is losing. Notably, the manually re-captured Canva screenshot for this case *also* shows the same generic-food-product mismatch Curify shows (not a hard zero-result as first reported), reinforcing that this is a segmentation/retrieval weakness pattern that can appear on any platform with weaker Chinese query handling, not a Curify-specific content gap.
- **Suggested fix direction:** Chinese segmentation improvements (see PR candidates below) — specifically, protect multi-character qualifying prefixes (低饱和, 国风, 私域, 手冲) from being dropped during tokenization, likely via a Chinese-specific compound-noun dictionary or n-gram-aware segmentation model.

### 8. NER / named-entity issue

- **Affected query count:** ~8-10 queries with clear proper-noun/IP/brand entities dropped (inferred; overlaps with `wrong_decomposition`)
- **Representative queries:** NCT Dream photocard template (K-pop group name); Love and Deepspace card pack design (game title); genshin impact Furina fanart wallpaper 4k (game + character name); 光与夜之恋 卡面设计参考图 (game title, Chinese); Amazon EBC / Amazon Vine (brand + product-line acronyms)
- **Likely cause:** Proper nouns, franchise/IP names, and brand-specific acronyms are not being recognized as protected named entities before decomposition runs, so the decomposition step treats them as ordinary dictionary words and matches on a leftover generic token instead.
- **More likely:** Retrieval issue (a specific pre-retrieval NLP step — entity recognition — rather than the decomposition/matching step itself, though the two are closely coupled).
- **Evidence from Curify screenshots:** `NCT Dream photocard template`'s screenshot is the clearest example: Curify's own broadened-query banner names the correct entity ("NCT Dream photocard design") yet the returned grid still matches on "dream" alone (Dream of the Red Chamber) — strong evidence the entity was recognized at some point in the pipeline (enough to generate a broadened suggestion) but not carried through to the actual retrieval call.
- **Evidence from Bing/Google/Canva/Pinterest screenshots:** Visually confirmed for `NCT Dream`, `genshin impact Furina`, and `光与夜之恋` — all three get precise, abundant, correctly-entity-matched results on Bing/Google/Pinterest (e.g., Pinterest returns NCT Dream-branded "Dreamscape Album Photocard Template" pins by name). This is the strongest evidence that the entity itself is a well-known, well-indexed concept elsewhere — Curify's pipeline is the outlier.
- **Suggested fix direction:** NER generalization / named-entity protection (see PR candidates below) — the top-priority fix given how cleanly it's evidenced.

### 9. Alias / synonym gap

- **Affected query count:** ~6-8 queries using fandom, platform, or industry-specific vocabulary (inferred)
- **Representative queries:** NCT Dream **photocard** template (fandom term); Amazon **EBC/A+** enhanced brand content layout (industry acronym); TikTok **GRWM** product placement mockup (platform-specific acronym); 小红书探店打卡**九宫格** (platform-specific layout term, "nine-grid"); RTI intervention tracker (education acronym); WIDA can-do descriptors (education acronym)
- **Likely cause:** Curify's internal taxonomy/vocabulary likely doesn't have these domain-specific terms mapped to their general-purpose equivalents (photocard → trading-card/ID-card template category; EBC/A+ → Amazon listing-image template category; GRWM → "get ready with me" beauty/lifestyle video template category).
- **More likely:** Taxonomy issue — this is fundamentally about vocabulary mapping into Curify's internal category system, not a raw retrieval-algorithm bug.
- **Evidence from Curify screenshots:** `Amazon EBC enhanced brand content layout` returns a hard zero rather than any adjacent Amazon-listing-template content, consistent with "EBC/A+" not being mapped to any internal category at all (as opposed to being mapped to the *wrong* category, which would at least return something).
- **Evidence from Bing/Google/Canva/Pinterest screenshots:** Visually confirmed for the EBC case — Pinterest has a pin literally tagged/titled "EBC / A+ Content," proving this is established, searchable vocabulary elsewhere.
- **Suggested fix direction:** Alias expansion (see PR candidates below) — build a fandom/platform/industry-term-to-category alias table, prioritized by frequency in the query logs.

### 10. Content library gap

- See the dedicated "Content-Library Gaps" section below — this category is intentionally separated from the code-fixable categories above because search-algorithm changes alone cannot resolve it.

### 11. Ranking / fallback issue

- **Affected query count:** ~5 queries showing partial-relevance signal mixed with off-topic clutter in a low result set (inferred)
- **Representative queries:** Amazon brand story module design (2 results: one loosely on-topic "Brand IP Display Board," one unrelated "capybara jiangyuan" character IP); 儿童安全座椅品牌视觉 (baby-care brand loosely adjacent, rest unrelated); 二手奢侈品鉴定品牌视觉 (one loosely-luxury e-commerce template among unrelated items); 宠物摄影工作室品牌设计 (pet subject present but mixed with unrelated food/anime); IEP accommodations checklist visual (1 of 3 counted results rendered, and that one is unrelated)
- **Likely cause:** Unlike the hard-zero or fully-wrong-topic cases, these show the retrieval layer surfacing *some* correct signal but the ranking/fallback logic isn't confidently separating the 1-2 relevant hits from clutter, and isn't broadening the candidate pool enough to bury the clutter under more good results.
- **More likely:** Retrieval issue specifically at the ranking/fusion stage, distinct from decomposition (the query concept was partially recognized) — this is a narrower, more surgical fix candidate than the broader decomposition fixes.
- **Evidence from Curify screenshots:** `Amazon brand story module design`'s screenshot shows exactly this pattern — 2 results, one genuinely relevant, one a random unrelated character IP, with no attempt to broaden past 2 results despite the obvious low count.
- **Evidence from Bing/Google/Canva/Pinterest screenshots:** Not yet visually cross-referenced for this specific group (none of these 5 were in the 12-case competitor sample) — flagged as a next-round candidate for competitor comparison.
- **Suggested fix direction:** Ranking / fallback adjustment (see PR candidates below) — when result count is low but at least one result scores above a relevance threshold, broaden the candidate pool automatically rather than returning a thin, mixed-quality set.

### 12. Gallery image recall issue

- **Affected query count:** 0 by the literal `gallery_under_recall` tag (measurement limitation, not a clean bill of health — see below); 6 queries flagged for manual gallery-recall check in the prior summary
- **Representative queries:** dreamcore aesthetic moodboard; weirdcore aesthetic sticker design; genshin impact Furina fanart wallpaper 4k; 故障艺术风格海报 (glitch-art poster); 松弛感生活方式插画; heritage brand rebrand moodboard; dress to impress historical royalty outfit inspo
- **Likely cause:** The `top_10_result_types` column only ever contains `inspiration` or `template` — there's no distinct "gallery" type to check against, so this tag structurally cannot fire under a literal reading even when a moodboard/aesthetic query returns topically-wrong "inspiration"-typed results (format matched, subject didn't).
- **More likely:** This is a **measurement/instrumentation issue**, not conclusively a retrieval, taxonomy, or content issue — the underlying queries in this group are already captured under `wrong_decomposition`/`bad_relevance`, so the root cause there likely applies, but a genuine gallery-specific recall problem cannot be ruled in or out without a dedicated visual pass.
- **Evidence from Curify screenshots:** `genshin impact Furina fanart wallpaper 4k`'s screenshot (one of the 12 visually-reviewed cases) shows exactly 3 `inspiration`-typed cards render, captioned "friends," "howls moving castle," "neighbor totoro" — correctly typed as gallery/inspiration format, completely wrong subject.
- **Evidence from Bing/Google/Canva/Pinterest screenshots:** Not directly informative for this category specifically — competitor comparison confirmed the subject-matter gap (see NER section above) but wasn't designed to test gallery-type recall as a separate axis.
- **Suggested fix direction:** Gallery image recall expansion (see PR candidates below) — but treat this as lower-confidence than the other categories until a dedicated visual pass (opening live result grids, not relying on the `top_10_result_types` column) is run specifically to test gallery/inspiration-type recall independent of subject-matter relevance.

## Content-Library Gaps

These four clusters showed up repeatedly across the 68-query set and are flagged separately because **a retrieval-algorithm fix alone will not resolve them if the underlying content genuinely isn't in Curify's library** — that determination itself requires a product/content decision, not just an engineering PR.

- **Amazon / e-commerce operational assets** — Amazon EBC/A+/Vine, TikTok GRWM mockups, 社群接龙团购价目表, 私域用户运营SOP流程图, 私域裂变任务宝海报. 7 of the 11 zero-result queries fall in this cluster. **Caveat:** the one visually-tested case in this cluster (Amazon EBC) turned out to be a strong *retrieval* gap (Bing/Google/Pinterest all have abundant EBC/A+ content), so this cluster needs case-by-case competitor verification before assuming it's a pure content gap — some of these 7 may resolve via the alias-expansion PR above rather than content sourcing.
- **Fandom / IP content** — NCT Dream, Genshin Impact/Furina, Love and Deepspace, 光与夜之恋. **Caveat:** visually confirmed as predominantly a *retrieval* gap, not a content gap, on Bing/Google/Pinterest — but Canva specifically does appear to have a genuine content gap for licensed anime/game character art (confirmed on `genshin impact Furina fanart wallpaper 4k`, where even a manually re-captured, logged-in Canva screenshot showed zero relevant content). If Curify's own template library (as opposed to raw retrieval) also lacks licensed IP art the way Canva's does, this cluster could still have a real content-supply component underneath the retrieval bug — worth checking Curify's inventory directly, not just its search behavior.
- **Special education / homeschool content** — IEP accommodations checklist visual, zones of regulation poster classroom, first then board autism, WIDA can-do descriptors chart, RTI intervention tracker template, charlotte mason copywork printable, loop schedule homeschool printable, newcomer welcome kit printable. **Caveat:** the two visually-tested cases (IEP, zones of regulation) were both strong retrieval gaps — competitors have abundant content — suggesting this cluster is more likely a retrieval/alias problem (education-sector acronyms and terminology not mapped) than a true content gap, but this is inferred from only 2 of 8 cases.
- **Brand packaging / product mockup formats** — clean girl aesthetic skincare packaging mockup, 国货美妆联名限定包装, 低饱和国风茶包装设计. **Caveat:** the one visually-tested case (低饱和国风茶包装设计) was a retrieval/segmentation gap, not a content gap (competitors have abundant matching packaging design content) — but packaging-mockup as a *format* (as opposed to packaging-design *imagery*) may still be genuinely under-supplied in Curify's template library; this format-vs-imagery distinction hasn't been specifically tested.

**Overall recommendation:** none of these four clusters should be assumed to be pure content gaps without a case-by-case competitor check — the pattern in every cluster where a competitor check *was* run points toward retrieval/taxonomy causes being more responsible than raw content absence. Recommend running the same 4-platform screenshot comparison on a larger sample from each cluster before committing content-sourcing resources.
