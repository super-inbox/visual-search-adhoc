# Curify Expanded Query Eval & Search Relevance Fix 工作报告 — 2026-07-09

## 1. 本轮工作的目标和老板要求

本轮不是单次任务，而是从「查询扩展 → 搜索测试 → 问题诊断 → 视觉验证 → 归因分析 → 真实代码修复」的完整链路。老板的核心要求可以拆成这几条：

1. **新的 eval 集合要和原始 58 条 baseline 挂钩**，不能是一套脱节的新体系——要能说清楚新东西是从老东西怎么长出来的。
2. **扩展出的 1,000+ 条 query 候选，定位是"更大的搜索压力测试候选池"**，不是"已经跑完的结果"——这个边界必须讲清楚，避免以后被误解成"1000 多条都测过了"。
3. **用这些 query 去实际暴露 Curify 搜索的问题**：零结果、结果太少、相关性差、query 被错误拆解（wrong decomposition）、召回缺口。
4. **针对暴露出来的问题，研究并提出修复方向**：命名实体（NER）保护、中文分词、别名（alias）、语义替换、兜底（fallback）策略。
5. **用扩展 query 反哺 taxonomy / 三层本体（3-tier ontology）**，把"哪些内容类型/形式是系统性缺失的"整理出来。
6. **区分"缺内容类型"和"缺具体某个主题"**——这两者优先级不一样，缺内容类型影响面更大。
7. **检查 gallery 图片召回情况**。
8. **在把这些 query 用于自动生成图片之前，先做安全性评估**。

今天完成的工作覆盖了 1-6 和 7、8 的**分析/诊断层面**；同时在诊断的基础上，已经在 curify-frontend 里落地了两轮**真实的代码修复**（不属于老板今天的清单，是诊断发现问题后主动往前推进的部分）。

## 6. 关键发现

用简单的话总结这轮诊断的核心结论：

- **大部分失败是"query 理解/检索匹配"层面的问题，不是 query 本身无效。** 也就是说，不是用户问了个奇怪的问题，而是 Curify 没理解对。
- **命名实体和固定短语会被错误拆解**：系统会抓住 query 里一个高频通用词，丢掉真正限定意图的部分。例如 "NCT Dream photocard template" 被拆成了通用词 "dream"，匹配到了《红楼梦》相关内容；"maker space label set printable" 被拆成了 "space"，匹配到了外太空/航天内容。
- **中文复合短语会被拆成误导性的二字词组合（bigram）**：比如 "光与夜之恋 卡面设计参考图"，"卡面设计"被拆成"卡面"+"面设"+"设计"这类无意义的二字组合，导致匹配到完全无关的内容（色板卡片、室内设计 moodboard 等）。
- **有些"结果数量看起来多"其实是全错的假象**：比如某个 query 显示 rich（返回了 20+ 条结果），但打开一看这些结果 100% 都是错的——数量本身不能代表质量，这是本轮诊断中一个反复出现的陷阱。
- **修复后出现"结果变少甚至变空"，有时反而是更诚实的表现**：因为之前的"结果多"是误报（false positive），修复后把误报清掉了，剩下的结果虽然少，但是真正相关的；如果没有真正相关的内容，返回空结果也比返回一堆错误内容更诚实。
- **有些看起来像"缺具体主题"的 gap，实际上是检索匹配问题，不是真的没内容**：如果拿同一个 query 去 Bing/Google/Pinterest 搜，能搜到大量相关内容，说明这个概念是存在的、是可检索的，只是 Curify 内部没匹配上——这种情况不能简单归类为"内容库缺失"。
- **"缺内容类型"比"缺某一个小众主题"更值得优先关注**：因为内容类型的缺失会影响未来所有需要这个格式的 query（比如"打印标签"这个格式），而单个主题的缺失只影响这一个实体。

**典型案例：**

| Query | 问题类型 | 现象 |
|---|---|---|
| NCT Dream photocard template | 命名实体被拆解 | 匹配到"dream"通用词，出来《红楼梦》相关内容 |
| maker space label set printable | 命名实体/复合词被拆解 | 匹配到"space"，出来外太空/航天内容 |
| 光与夜之恋 卡面设计参考图 | 中文复合短语被拆解成误导性二字词 | 匹配到色板卡片、室内设计 moodboard，与游戏无关 |
| 小红书香薰产品种草图 | 平台名+营销术语造成误匹配 | 之前显示"结果多"，实际全部来自一个不相关的服饰电商模板（因为该模板简介里恰好提到"小红书种草内容创作者"这类通用受众描述） |
| 手冲咖啡工作室视觉手册 | 通用词二字组合误匹配 | "工作室"+"视觉"匹配到民族服饰版和动画工作室对比模板，与咖啡毫无关系 |
| Amazon EBC enhanced brand content layout | 零结果，疑似缩略词未识别 | Curify 返回"无结果"，但 Bing/Google/Pinterest 上都能搜到大量真实的 EBC/A+ Content 内容 |
| zones of regulation poster classroom | 缺内容类型 | Curify 返回的是通用词汇卡片，Bing/Google/Canva/Pinterest 四个平台一致返回了正确的"情绪分区"海报格式 |

## 8. 已经落地的 curify-frontend 修复

以下内容基于对 curify-frontend 的**实际 git 状态检查**（分支：`baobao/search-relevance-phrase-alias-2026-07-09`），不是计划，是已经发生的事实。

### Fix 1：短语级保护 + 别名注入

**做了什么：** 在 Curify 搜索的 query 分词逻辑里加入了一层"短语规则"机制——对特定的命名实体/固定短语，(1) 阻止它们被拆解成误导性的通用词或字符组合，(2) 在合适的情况下注入英文/中文别名，帮助匹配到真正相关的内容。同时修复了一个"template"这个词本身被误当作有效匹配信号的 bug（因为几乎每个模板 ID 里都含有"template"这个词，导致任何提到"template"的 query 都会被无脑加分）。

**效果举例（均已用真实 catalog 数据验证）：**

| Query | 修复前 | 修复后 |
|---|---|---|
| NCT Dream photocard template | 显示"结果较多"（4 条），但全部是错的——匹配到"dream"这个通用词，出来的是《红楼梦》相关卡片 | 结果清零（0 条）——错误匹配被清除，目前没有真正相关内容可以替代（内容库缺口，非本次修复范围） |
| 光与夜之恋卡面设计参考图（无空格） | 显示"结果丰富"（13 条），但全部是错的——中文被拆成误导性二字词，匹配到色板卡片、室内设计 moodboard | 结果清零（0 条）——同上，错误匹配清除，暂无替代内容 |
| Amazon EBC enhanced brand content layout | 相关模板信号被淹没在 11 个不相关的模板噪音里 | 收窄到 1 个真正相关的 Amazon 模板 |

**这次修复的性质：主要是"精确率/误报控制"（precision / false-positive control），不是"内容库召回扩充"。** 也就是说，Fix 1 解决的是"系统自信地给出错误答案"这个问题，而不是"系统没有相关内容可以推荐"这个问题——后者需要内容库补充，超出了这次代码修复的范围。

### Fix 2：中文复合短语保护

**做了什么：** 在 Fix 1 的同一套机制上，新增了 3 条中文短语规则：`小红书`、`手冲咖啡`（附带"brand identity / visual identity"英文别名）、`二手奢侈品`。用来阻止这些短语所在的 query 被拆成误导性的中文二字词组合。

**效果举例：**

| Query | 修复前 | 修复后 |
|---|---|---|
| 小红书香薰产品种草图 | 显示"结果丰富"（23 条），**但全部是错的**——全部来自一个不相关的服饰电商模板（eyemask、挂饰、耳环等），因为该模板简介里恰好提到"小红书种草内容创作者"这类通用受众描述文字 | 结果变为"中等"（6 条），**全部是真正的香薰/精油相关内容** |
| 手冲咖啡工作室视觉手册 | 显示"结果丰富"（11 条），但匹配到民族服饰版、动画工作室对比模板，与咖啡完全无关 | 结果仍为"结果丰富"（16 条），但内容变成了品牌视觉识别（brand identity）模板家族，其中包含真正的咖啡品牌案例 |
| 二手奢侈品鉴定品牌视觉 | 显示"结果中等"（31 条），但全部来自一个不相关的服饰电商模板 | 结果清零（0 条）——目前确实没有二手奢侈品鉴定相关内容，清零是诚实的结果 |

**重要说明：从"结果多"变成"结果少甚至为 0"，在这两次修复里都是质量提升，不是功能倒退。** 之前的"多"是虚假的高召回（全错），修复后的"少"是真实的高精确率。这一点在测试用例的命名和 eval 记录里都做了明确标注，避免以后被误读成"改坏了"。

## 9. Taxonomy / 3-tier ontology 沉淀

从 1,118 条扩展 query 候选池里，产出了一份 **1,118 行的 taxonomy 候选表**（`taxonomy_candidates_from_expanded_queries_2026-07-09.csv`），用三层本体做首轮映射：

- **Tier I —— 主题/实体/事件**：query 到底是关于什么的？（比如护肤品、教室、亚马逊卖家、NCT Dream、茶包装）
- **Tier II —— 信息类型/内容功能**：这个结果需要承担什么功能？（比如清单、追踪表、对比、流程图、活动卡片）
- **Tier III —— 排版/视觉格式**：最终应该长什么样？（比如海报、卡片、清单、九宫格、包装样机、SOP 流程图）

**识别出的高优先级内容类型缺口**：

- 清单类可视化（checklist visuals，如 IEP 无障碍支持清单）
- 活动卡片（activity cards，如 STEM/编程教学卡）
- 教室海报/流程海报（如"情绪分区"海报）
- 标签套装（label sets，如创客空间打印标签）
- 卡面/卡牌设计参考图（photocard / card design reference）
- 包装样机（packaging mockups）
- 品牌发布视觉（brand launch visuals）
- 亚马逊/电商运营类素材（EBC/A+、Vine 评价卡）

## 10. Gallery image recall 分析

**结论：现有数据结构测不出 gallery 召回是否健康，不能说"没问题"，只能说"测不出来"。**

具体原因：

- 当前 `top_10_result_types` 这个字段里，只出现过 `inspiration` 和 `template` 两种取值，**没有独立的 `gallery` 类型**。
- 按字面标准（"moodboard/美学/壁纸类 query 如果没有返回 gallery 类型结果就标记为召回不足"）去检查，`gallery_under_recall` 在全部 68 条里命中 0 次——但这是因为这个标签**结构性地无法触发**，不是真的没问题。
- 已经发现的真实现象是：不少 moodboard/美学/壁纸类 query 确实返回了 `inspiration` 类型的结果（格式对了），但**主题完全不对**（比如"dreamcore aesthetic moodboard"返回了咖啡店、面包店的品牌 moodboard）——这说明问题出在"匹配到了错的主题"，而不是"gallery 这种格式被系统性压制"。
- 对 7 个专项检查的 case 逐一核实后，**没有一个 case 显示出独立于其他问题（分词、实体识别）之外的"gallery 专属"召回问题**——所有 7 个都能归到本报告已经记录的其他原因（分词、命名实体、检索匹配）上。

**下一步建议**：单独建一个 15-20 条的"gallery 专项 eval 集合"，并且在采集时就区分 gallery / template / 其他 inspiration 三种类型，而不是事后从现有字段里反推。

## 11. Safety notes

**核心原则：一个 query 适合用来测试搜索召回，不代表它可以直接拿去做自动生成图片的 prompt。** 搜索只是从已有的、已经过审的内容里检索；生成是创造全新内容，风险性质完全不同。

**审查的风险类别**：殡葬（funeral）、色情（sexual）、医疗疾病（medical disease）、皮肤病（skin disease）、暴力（violence）、身体异常（body abnormality）、敏感文化/宗教内容、IP/版权、美容/医美宣称、未成年人/教室/无障碍相关内容。

**代表性发现**：

- `宠物殡葬服务品牌视觉设计`、`殡葬服务行业品牌视觉设计` —— 命中"殡葬"关键词，标记为 **needs_review**（商业品牌语境，非严重风险，但生成前建议人工过一遍）。
- K-beauty / 医美机构品牌视觉设计 / glass skin 相关 query —— 标记为 **needs_review**，原因是"美容宣称邻近性"（品牌宣传图暗示疗效），而非直接的医疗疾病内容。
- NCT Dream / Genshin Impact（原神）/ 光与夜之恋 / Chiikawa（吉伊卡哇）等粉丝向/IP query —— 标记为 **search_eval_only**（仅限用于搜索测试），原因是**版权/IP 风险**，而不是内容安全风险：搜索这些 query 没问题（只是检索已存在的内容），但拿来做生成会涉及版权角色的新图像生成，是完全不同性质的决策。
- **明确没有过度标记**：`家用医疗器械品牌设计`（医疗器械品牌设计）、`first then board autism`、`IEP accommodations checklist visual`、`zones of regulation poster classroom` 等特殊教育/无障碍相关 query 被明确标记为 **safe**——这些是合法、良性的教育/商业设计需求，不应该因为词面上出现"医疗""自闭症"就被误伤。

**结论：本轮扫描的全部 1,186 条 query 字符串（68 条已执行 + 1,118 条候选池）中，没有一条命中需要"exclude_from_generation"（完全禁止生成）的级别；殡葬类（2 条）、IP/粉丝向类（18 条）、身体/皮肤/美容宣称类（4 条）需要 needs_review 或仅限搜索测试。**
