Each entry lists what to trigger and how to observe it, based on the Stage 2 code audit (`02_PRODUCTION_SEARCH_CODE_AUDIT.md`, `03_PRODUCTION_SEARCH_CALL_GRAPH.md`).

## Notes on rigor

- Per the task's explicit requirement, "file exists" is never treated as sufficient evidence for PASS on any of the above — Stage 3/11 must show an actual triggered request/response (via the harness or Playwright) with an observed effect (non-empty `usedRewrites`, a rendered banner string, a changed result count, etc.), not merely confirm the relevant source file is unchanged.
- Items 5-6 (L2 / multi-paragraph) are carried into Stage 3/11 as explicit UNKNOWN rows, not silently dropped — this is the honest treatment required by the task spec ("若L2或多段落无法确认... 标记UNKNOWN，不得伪造PASS").
- V2 development scope is deliberately restricted to `page.tsx` (merge/scoring/gating logic), `lib/searchRewrite.ts` (subject binding, phrase protection input), and new scorer/config modules — it does **not** touch `GenerableTemplatesSection.tsx`, `NanoTemplateDetailClient.tsx`, `ExampleImagesGrid.tsx`, `services/searchGenerationBatch.ts`, or any topic-page code, which keeps items 5, 6, 9, 10, 12 structurally low-risk even where they can't be positively re-verified end-to-end.
