# Curify 搜索相关性优化 — 摘要（2026-07-13 至 2026-07-14）

## 做了什么

**7.13**：完成第一轮真实端到端验证（用真实生产代码，非 mock，跑通完整审计+实现+68 条 Hard Query A/B/C/D 消融）。结果如实汇报：Strict PASS 仅 0.0%，远低于 60%-80% 目标，且发现一个此前未被量化的系统性问题——**LLM Rewrite 产生的通用词与新分词逻辑结合后，会在 23/68（34%）条查询上把搜索结果灌成上千条甚至整个 3209 条目录**，这是当时最大的生产阻塞项。

**7.14**：针对性做了四轮 Guard 补强（逐步把结果洪泛压下去）、修复了实验设计本身的一处合法性问题（此前"关闭新分词特性"的对照组是靠读取旧代码文本重建的，不是同一份生产代码的两种运行状态；发现后新增了真正的开关，重新做了合法实验）、完成合法的 68 条查询完整重跑、独立人工复核、12 个代表性案例的真实截图前后对比、以及剩余问题的根因/责任人整理，最后生成了一套清晰的优化前后数据对比材料。

## 结果

68 条 Hard Query 中，**达到"完全通过或部分改善"的比例从 5.9% 提升到 67.6%**，**严重失败（FAIL）数量从 64 条降至 22 条**。最明确的改善是**结果洪泛问题**：超过 1000 条结果的异常从 23 条降至 2 条（下降 91.3%），"返回整个目录"这种最严重的失败形式已经清零。

**但 67.6% 不等于"67.6% 完全修复"**——这 42 条"部分改善"里，约有一半仍然是 0 结果，只是因为系统判断这是"目录里本来就没有这个内容"而不是"算法出错"，才没有被计入失败。真正代表用户能感知到搜索变好的比例，大约在 26% 左右。

## 12 个 P0（代表性高优先级案例）

用真实截图逐条重新核实（不只看结果数字），结果是 **0 条完全通过、5 条部分改善、7 条仍然失败**。没有一条可以作为"已经修好了"的证据。4 条存在真实可见的改善（比如低饱和国风茶包装从完全不相关变成前几条真实相关），但都没有达到完全修复的程度。

## 剩余问题

22 条仍然失败的查询里，**14 条（64%）的根因是目录里压根没有这类内容**（比如某些小众 IP、特定风格词、小红书/抖音等社交电商运营黑话），这需要内容团队去采购/生产内容，不是靠改代码能解决的。剩下的是 4 条已知的匹配阈值问题、3 条分词器精度回归、1 条把查询实体搞错（NCT Dream 被搜索系统当成了另一个组合 ILLIT）。

## 当前限制

**300+ 普通查询的验证正在并行进行中**，本次报告还没有等它跑完，因此现在还不能说"普通查询已经确认没有受到影响"——已知在 68 条困难查询里有 5 条是因为已上线的新分词器导致的回归，说明这个风险类别是真实存在的，但样本本身不包含真正意义上的简单查询，不能直接外推。此外，Taxonomy 分类体系的相关工作（1,118 条候选审计、Dry-run、导入）目前都还没有开始。
